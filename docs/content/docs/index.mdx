devproxy gives each Git worktree a predictable local HTTPS URL, such as `https://kasta-feature-login.localhost`. One dedicated Caddy instance handles TLS and forwards requests. The `devproxy` daemon manages routes, while the CLI starts or registers development services. Application traffic goes through Caddy, not the daemon.

This is an early local development tool for macOS and Linux. Services run on the host, or in a container with their HTTP port published to the host.

## How it works

1. Caddy owns local HTTPS and proxies requests to services on `127.0.0.1`.
2. `devproxy serve` runs the dashboard and control API on `127.0.0.1:7654`. It loads active routes into Caddy through Caddy's local admin API.
3. `devproxy run` starts a development command on a free port, or `devproxy register` attaches an existing service. Both keep their registrations alive while they run.

Open `https://devproxy.localhost` to see active services, or run `devproxy list`.
