## Prerequisites

- Go 1.24 or newer and Just to build the CLI. Node.js 22 or newer and npm are needed when rebuilding the dashboard.
- Docker Desktop on macOS, Docker with host networking on Linux or OrbStack, or a native Caddy installation.
- A service that listens on a host TCP port. Containerized services must publish that port to the host.

The CLI binary has no Node.js runtime dependency. Node.js is also used to develop this documentation site.

## Build the CLI

From the devproxy repository:

```sh
just build
```

Use `just go` to build from the checked-in dashboard assets without Node.js.
Use `bin/devproxy` in the commands below, or put the binary on your `PATH` and use `devproxy`.

## Start Caddy and the daemon

devproxy requires a **dedicated** Caddy instance with its admin endpoint at `http://127.0.0.1:2019`. The daemon owns that instance's configuration. Caddy also needs port 443, so stop any other local proxy using it first.

On Docker Desktop for macOS, run:

```sh
just serve-desktop
```

This uses a bridge network and publishes Caddy's ports only on the host loopback address. Keep `serve` running. On Linux Docker Engine or macOS OrbStack, use host networking instead:

```sh
docker compose -f caddy/compose.yml up -d
bin/devproxy serve
```

You can also run Caddy natively with the included `caddy/Caddyfile`.

Open `https://devproxy.localhost` for the dashboard. If your browser does not yet trust Caddy's local certificate, follow [Trust local HTTPS](#trust-local-https).

## Register a development service

Run this from the service's Git worktree. `--project` is a stable project name; the worktree folder supplies the instance name.

```sh
bin/devproxy run --project example web -- next dev -p '{port}'
```

`run` picks a free port, sets `PORT` and `DEVPROXY_URL`, replaces `{port}` in command arguments, waits for the port to listen, and registers its route. Keep the command running while you need the URL. Open `https://example-<worktree-folder>.localhost`.

For a service that is already listening on port 3001, keep a separate registration command running:

```sh
bin/devproxy register --project example --port 3001 api
```

Check active URLs with `bin/devproxy list` or the dashboard. See [CLI reference](/docs/cli) for all flags and [Routes and URLs](/docs/routing) for multiple services on one origin.

## Trust local HTTPS

The Compose volume retains Caddy's local certificate authority across restarts. On macOS, after Caddy has served its first HTTPS request, copy and trust the root certificate:

```sh
docker compose -f caddy/compose.desktop.yml cp caddy:/data/caddy/pki/authorities/local/root.crt ./devproxy-root.crt
security add-trusted-cert -d -r trustRoot -k "$HOME/Library/Keychains/login.keychain-db" ./devproxy-root.crt
```

The trust command may ask for your macOS password. On Linux, use `caddy/compose.yml` in the copy command and add the root certificate to your system or browser trust store using your distribution's process. The copied certificate is ignored by this repository's Git configuration.
