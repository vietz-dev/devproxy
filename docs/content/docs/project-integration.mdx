## Wrap a development command

Build the devproxy binary and put it on your `PATH`, then run a project's development command through `devproxy run`. Use one stable `--project` name across all of the project's worktrees. Run the wrapper from the Git checkout so it can derive the worktree name.

```sh
devproxy run --project kasta --url-env NEXT_PUBLIC_APP_URL web -- next dev -p '{port}'
```

The command starts Next.js on the chosen port and gives it `PORT`, `DEVPROXY_URL`, and `NEXT_PUBLIC_APP_URL`. The worktree's URL is `https://kasta-<worktree-folder>.localhost`. Keep the wrapper running while using the app.

If a project's `dev` script already wraps devproxy, run that script directly. The Kasta root uses `pnpm dev` after `devproxy start`; its web script registers the worktree and sets `NEXT_PUBLIC_APP_URL` automatically.

See [Routes and URLs](/docs/routing) when an API and frontend should share an origin. For an existing service that controls its own port, use [`devproxy register`](/docs/cli#register).

## Install the agent skill

The repository includes `skills/devproxy/SKILL.md`. It tells a coding agent how to start a devproxy project, find its URL, and list active services. From the project that will use devproxy, install it with the [skills CLI](https://skills.sh/docs):

```sh
npx skills add /absolute/path/to/devproxy --skill devproxy
```

Select the agent you use when prompted. The skill is installed in that project, so new agent sessions can use it. The repository README also describes a future shorthand for when the project is published at `github.com/dreifach-ai/devproxy`.
